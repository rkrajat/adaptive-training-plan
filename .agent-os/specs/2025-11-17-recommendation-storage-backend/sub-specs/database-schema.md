# Database Schema

This is the database schema implementation for the spec detailed in @.agent-os/specs/2025-11-17-recommendation-storage-backend/spec.md

## New Collection: recommendations

### Schema Definition

```typescript
import mongoose, { type Document, Schema } from 'mongoose';

export interface IRecommendation extends Document {
  userId: mongoose.Types.ObjectId;
  trainingPlanId: mongoose.Types.ObjectId;
  weekNumber: number;
  content: string;
  athleteInputFeedback?: string;
  isRegenerated: boolean;
  previousRecommendationId?: mongoose.Types.ObjectId;
  createdAt: Date;
  updatedAt: Date;
}

const recommendationSchema = new Schema<IRecommendation>(
  {
    userId: {
      type: Schema.Types.ObjectId,
      ref: 'User',
      required: true,
      index: true,
    },
    trainingPlanId: {
      type: Schema.Types.ObjectId,
      ref: 'TrainingPlan',
      required: true,
      index: true,
    },
    weekNumber: {
      type: Number,
      required: true,
      min: 1,
      validate: {
        validator: Number.isInteger,
        message: 'Week number must be an integer',
      },
    },
    content: {
      type: String,
      required: true,
      maxlength: 50000,
    },
    athleteInputFeedback: {
      type: String,
      maxlength: 1000,
      default: null,
    },
    isRegenerated: {
      type: Boolean,
      default: false,
    },
    previousRecommendationId: {
      type: Schema.Types.ObjectId,
      ref: 'Recommendation',
      default: null,
    },
  },
  {
    timestamps: true,
    collection: 'recommendations',
  }
);

// Compound index for efficient user history queries
recommendationSchema.index(
  { userId: 1, trainingPlanId: 1, weekNumber: 1, createdAt: -1 },
  { name: 'user_plan_week_date_index' }
);

// Index for efficient chronological queries
recommendationSchema.index(
  { createdAt: -1 },
  { name: 'created_date_index' }
);

export const Recommendation = mongoose.model<IRecommendation>(
  'Recommendation',
  recommendationSchema
);
```

### Field Specifications

| Field | Type | Required | Indexed | Constraints | Purpose |
|-------|------|----------|---------|-------------|---------|
| `userId` | ObjectId | Yes | Single | References User collection | Links recommendation to user who received it |
| `trainingPlanId` | ObjectId | Yes | Single | References TrainingPlan collection | Links recommendation to training plan context |
| `weekNumber` | Number | Yes | Compound | min: 1, must be integer | Identifies which week of training plan this recommendation is for |
| `content` | String | Yes | No | maxLength: 50000 | Full markdown content of the AI-generated recommendation |
| `athleteInputFeedback` | String | No | No | maxLength: 1000 | Athlete's input text provided when requesting the recommendation (e.g., "reduce intensity") - this is INPUT to AI generation |
| `isRegenerated` | Boolean | Yes | No | default: false | Flags if this is a regenerated version of a previous recommendation |
| `previousRecommendationId` | ObjectId | No | No | References Recommendation collection | Links to original recommendation if this is regenerated |
| `createdAt` | Date | Auto | Compound | Auto-generated by timestamps | When recommendation was generated |
| `updatedAt` | Date | Auto | No | Auto-generated by timestamps | Last modification time (rarely used) |

### Indexes

#### 1. Compound Index: user_plan_week_date_index
```javascript
{ userId: 1, trainingPlanId: 1, weekNumber: 1, createdAt: -1 }
```
- **Purpose**: Optimize queries for user's recommendation history filtered by plan and week
- **Use Case**: "Get all recommendations for user X, training plan Y, week Z, ordered by date"
- **Query Pattern**: `db.recommendations.find({ userId, trainingPlanId, weekNumber }).sort({ createdAt: -1 })`

#### 2. Single Index: userId
```javascript
{ userId: 1 }
```
- **Purpose**: Fast lookup of all recommendations for a specific user
- **Use Case**: "Get all recommendations for user X"
- **Query Pattern**: `db.recommendations.find({ userId })`

#### 3. Single Index: trainingPlanId
```javascript
{ trainingPlanId: 1 }
```
- **Purpose**: Find all recommendations associated with a training plan
- **Use Case**: Analytics or when displaying plan-specific recommendation history
- **Query Pattern**: `db.recommendations.find({ trainingPlanId })`

#### 4. Single Index: createdAt (descending)
```javascript
{ createdAt: -1 }
```
- **Purpose**: Efficient chronological sorting
- **Use Case**: "Get most recent recommendations across all users"
- **Query Pattern**: `db.recommendations.find().sort({ createdAt: -1 })`

### Relationships

```
User (1) ──────→ (N) Recommendation
                       ↑
                       │
                       │ references
                       │
TrainingPlan (1) ──────→ (N) Recommendation

Recommendation (1) ─────→ (0..1) Recommendation (previousRecommendationId)

Recommendation (1) ←────→ (0..N) Feedback
```

### Data Validation Rules

1. **userId**: Must reference valid User document
2. **trainingPlanId**: Must reference valid TrainingPlan document
3. **weekNumber**: Must be positive integer (≥1), should be validated against training plan's total weeks
4. **content**: Cannot be empty string, max 50,000 characters
5. **athleteInputFeedback**: Optional, max 1,000 characters - stores the `userFeedback` from API request
6. **isRegenerated**: Boolean only (true/false)
7. **previousRecommendationId**: If set, must reference valid Recommendation document

### Storage Considerations

#### Estimated Document Size
- **userId**: 12 bytes (ObjectId)
- **trainingPlanId**: 12 bytes (ObjectId)
- **weekNumber**: 4 bytes (Number)
- **content**: ~2-10 KB typical (50 KB max)
- **athleteInputFeedback**: ~0-0.5 KB typical (1 KB max)
- **isRegenerated**: 1 byte (Boolean)
- **previousRecommendationId**: 12 bytes (ObjectId)
- **timestamps**: 16 bytes (2 dates)
- **Metadata**: ~50 bytes (document overhead)

**Total per document**: ~2-11 KB typical, 51 KB maximum

#### Scaling Estimates
- **10 users**: ~20-50 documents (2-10 recommendations per user)
- **100 users**: ~200-500 documents
- **1,000 users**: ~2,000-5,000 documents
- **Storage**: ~4-25 MB for 1,000 users (very manageable)

#### Index Size
- **Compound index**: ~500 bytes per document
- **Single indexes**: ~100 bytes per document each
- **Total index overhead**: ~800 bytes per document
- **For 5,000 documents**: ~4 MB in indexes

### Migration Scripts

#### No Migration Required

This is a new collection with no existing data to migrate. However, there are existing `Feedback` documents with `recommendationId` fields that incorrectly reference training plan IDs.

#### Optional Cleanup Script (Post-Deployment)

After deploying the new recommendation storage system, you may want to clean up incorrect feedback references:

```javascript
// apps/api/src/migrations/cleanup-invalid-feedback-refs.js

// This script identifies feedback documents with invalid recommendationId references
// (referencing training plan IDs instead of recommendation IDs)

db.feedbacks.find({}).forEach(function(feedback) {
  // Check if recommendationId exists in recommendations collection
  const recommendationExists = db.recommendations.findOne({
    _id: feedback.recommendationId
  });

  if (!recommendationExists) {
    // Log invalid reference for manual review
    print('Invalid feedback reference found:');
    print('  Feedback ID: ' + feedback._id);
    print('  User ID: ' + feedback.userId);
    print('  Invalid Recommendation ID: ' + feedback.recommendationId);

    // Optional: Delete invalid feedback entries
    // db.feedbacks.deleteOne({ _id: feedback._id });
  }
});
```

**Note**: This cleanup is optional because the invalid feedback entries won't cause errors - they simply won't link to any recommendations. New feedback submissions will use correct recommendation IDs.

### Query Performance

#### Most Common Queries

1. **Get user's latest recommendation for specific plan/week**
```javascript
db.recommendations.find({
  userId: ObjectId("..."),
  trainingPlanId: ObjectId("..."),
  weekNumber: 5
}).sort({ createdAt: -1 }).limit(1)
```
- **Performance**: O(log n) - Uses compound index
- **Expected time**: <5ms for 10,000 documents

2. **Get user's recommendation history**
```javascript
db.recommendations.find({
  userId: ObjectId("...")
}).sort({ createdAt: -1 }).limit(20)
```
- **Performance**: O(log n + k) - Uses userId index + createdAt sort
- **Expected time**: <10ms for 10,000 documents

3. **Get single recommendation by ID**
```javascript
db.recommendations.findOne({ _id: ObjectId("...") })
```
- **Performance**: O(1) - Primary key lookup
- **Expected time**: <2ms

### Backup and Retention

- **Backup Strategy**: MongoDB Atlas automatic backups (as per tech stack)
- **Retention Policy**: Keep all recommendations indefinitely (low storage cost)
- **Archive Consideration**: If storage becomes concern (>100,000 docs), archive recommendations older than 2 years
- **GDPR Compliance**: Include recommendations in user data deletion workflow

### Security Considerations

1. **Access Control**: Always validate `userId` matches authenticated user before returning recommendations
2. **Content Sanitization**: Store content as-is (markdown), sanitize on display in frontend
3. **PII Protection**: Avoid storing user-identifiable information in `content` field
4. **Rate Limiting**: Apply rate limits to recommendation generation to prevent storage abuse
